# 养基场 FundFarm

把基金自选管理做成「养鸡游戏」：领养一只鸡 = 持有一只基金，涨跌变成产蛋与掉毛，让枯燥的持仓管理变得有趣。

需求文档见 [`docs/PRD-养基场.md`](./docs/PRD-养基场.md)，本仓库为 MVP（V1.0）实现。

## 技术栈

- 后端：Node.js + Express 4 + SQLite（better-sqlite3）
- 前端：原生 ES Module SPA（hash 路由）+ CSS 变量主题，无构建步骤
- 鸡的形象：SVG 动态生成（随品种、等级、状态变化），无外部素材依赖
- 行情：服务端代理第三方公开基金接口，带缓存、降级与失败兜底

## 快速开始

```bash
npm install
cp .env.example .env        # 修改 SESSION_SECRET 等
npm start                   # 默认 http://127.0.0.1:3290
```

首次打开页面可用「游客模式」直接进入，也可注册账号（数据会保存在服务端 SQLite）。

可选：在 `.env` 中配置 `HUNYUAN_API_KEY`，即可使用大模型解析上传的研究报告；未配置时自动退化为本地摘要，功能不受影响。

## 搜索

领养弹窗的基金搜索带**自动联想补全**（`public/js/autocomplete.js`）：

- 输入代码、名称或拼音首字母（如 `005827` / `易方达蓝筹` / `yfdlc`）即触发防抖联想（250ms，请求带序号防竞态）
- 支持 ↑↓ 选择、回车确认、Esc 关闭；鼠标点击同样可选
- 选中后自动填充基金代码与昵称，联想数据来自 `/api/v1/search`（服务端 10 分钟缓存）

## 每只基金一只不同的鸡

品种（breed）由基金类型决定（股票型=斗鸡、指数=白羽鸡、混合=芦丁鸡、债=芦花鸡、QDII=异域凤冠鸡…），
同一品种下的不同基金再用**基金代码派生外观**（`src/engine/chicken.js` 的 `lookOf`），所以两只指数基金的鸡也长得不一样：

| 维度 | 取值 |
| --- | --- |
| 体色 | 品种基础色在 HSL 空间做色相/明暗偏移（近白色品种走色温 + 明度区间，避免荧光色） |
| 图案 | 纯色 / 圆点花 / 条纹 / 拼色 / 白肚 / 麻点（裁剪在身体轮廓内） |
| 配饰 | 无 / 围巾 / 眼镜 / 蝴蝶结 / 铃铛 / 小帽 |
| 鸡冠 | 三瓣 / 云冠 / 单冠 / 绒球 |
| 尾巴 | 扇形 / 卷翘 / 长翎 / 短尾 |
| 体型 | 四种比例（胖瘦高矮、头围、腿长） |

外观由 `hash32(基金代码|品种)` 稳定派生，换设备、重装、重新登录都不会变；
等级只影响体型缩放与金鸡光环，不会改变花色。

鸡舍 / 自选卡片副标题显示的是**实际基金分类**（东财 `FTYPE`，落到 `funds.category`），例如
`指数型-股票`、`指数型-海外股票`、`混合型-偏股`、`债券型-信用债`、`货币型-普通货币`；
品种与花色名（如「白羽鸡·麻点·眼镜」）保留在 `title` 提示与详情页，指数基金还会在「基金档案」里显示跟踪指数。

## 涨跌幅实时刷新

涨跌幅不是「打开页面那一刻」的快照，而是在页面停留期间持续更新：

- 前端 `public/js/live.js` 轮询 `GET /api/v1/quotes`（交易时段 20s、非交易时段 120s，页面切后台暂停、切回前台立即补刷）
- 只就地更新带 `data-live-*` 标记的节点（涨跌幅、估算净值、今日估算、涨/跌家数、大盘），不整页重渲染，不打断滚动
- 服务端该接口要求数据不老于 15s（`estimateCache` 常规 TTL 60s，实时模式按「写入时间」判定），且同一基金并发回源自动合并
- 接口只读，不结算鸡的成长值 / 饱食度，轮询不会把鸡刷饱

盘中涨跌幅的取值顺序：

1. 天天基金 `fundgz` 实时估值（当前该接口大面积 404，基本取不到）
2. **按持仓实时估算**：取最新披露的前十大持仓（天天基金 f10，缓存 7 天）+ 个股实时行情（腾讯 `qt.gtimg.cn`，缓存 30s），按占净值比例加权得出 `Σ(权重 × 个股涨跌)`；持仓覆盖率 ≥ 50% 才采用，标记为 `approx: true`、界面显示「按最新持仓实时估算」
3. 都不可用时退回最新净值日涨跌幅（`live: false`，界面提示「数据可能延迟」）

## 净值走势图与区间切换

- 数据源：详情页用 `pingzhongdata` 一次取回**成立以来全部净值**（`quote.getFullHistory`，缓存 6h，最多保留最近 1500 个交易日），
  兜底走 `f10/lsjz` 翻页；`f10/lsjz` **单页最多 20 条**，`quote.getHistory` 已按 `pageIndex` 翻页凑够所需条数
  （早期只取第一页，导致只有 20 个点，30/60/180/全部 四个区间画出来一模一样）
- 区间按**自然日**筛选：30 / 60 / 180 天取 `最后净值日 - N 天` 之后的数据，「全部」= 后端返回的全量
- 切换只重画图卡片（`[data-chart-slot]` 局部替换），不整页重渲染、不重新请求接口，点击即时生效

## 净值走势图细节

基金详情页的走势图是自绘 SVG（`public/js/chart.js`，无图表库依赖）：

- 平滑曲线（Catmull-Rom 转贝塞尔）+ 渐变面积，**涨红跌绿**按所选区间的整体涨跌取色
- 虚线网格 + 右侧净值刻度 + 首/中/末日期 + 区间最高/最低点标记 + 最新点高亮
- 指针移动（含触摸）显示十字准星与提示气泡：日期、净值、较区间起点涨跌
- SVG 用 `viewBox` + `preserveAspectRatio="none"` 自适应宽度，描边走 `vector-effect` 保持粗细，刻度与圆点用 HTML 定位，避免非等比缩放导致文字变形
- 后端 `quote.getHistory()` 统一把历史净值按日期**升序**返回（天天基金原始数据是倒序）

## 报告模块

导航中「报告」页是报告总库：

- 列出全部已上传报告，支持关键词搜索（标题/基金名/代码）与筛选（全部 / 未关联 / 已关联）
- 列表只显示**人能读懂的纯文本摘要**（HTML 报告先剥掉 `<script>/<style>/<head>` 与标签），解析状态、原文与 HTML 源码都放进「查看」详情里，不在列表堆标签
- **新增**（三种方式）：
  - `上传文件`：PDF / MD / TXT / CSV / **HTML** / 图片，≤20MB
  - `粘贴文本`：直接粘贴 Markdown、纯文本或 HTML 源码（格式可选「自动识别」）
  - `开放接口`：生成给 AI 的调用提示词，复制给任意 AI 助手即可让它生成报告并调用开放接口写入报告库（见下）
- **查看 / 重新解析 / 删除**：
  - **HTML 报告**：点「全屏打开」直接在新标签打开原文 `GET /api/v1/reports/{id}/raw`，**整屏渲染上传的 HTML 本体**（带严格 CSP，脚本不执行、外链不加载；缺 viewport 时后端自动补一个，手机上不会缩成小字）
  - **Markdown / 文本 / 文件**：跳到报告详情页 `#/report/{id}?from=reports|fund/{code}`（带来源返回按钮），展示 AI 摘要/要点/风险与正文
- **关联管理**：未关联的报告可一键「关联基金」，已关联的可「更换关联」

### 开放接口与 AI 提示词

「新增报告 → 开放接口」提供两份可一键复制的提示词（HTML 格式为默认且重点支持）：

- 提示词内含完整接口说明（端点、Header、请求体 JSON 示例、错误码约定）
- HTML 版要求 AI 输出**自包含 HTML**：样式写在 `<style>` 内联标签、不引用外部 CDN / 图片 / 字体、**不含 `<script>`**、移动端友好、结尾附免责声明且不出现投资建议表述
- 前端预览 HTML 报告时使用 `<iframe sandbox>`（不开启 `allow-scripts`）+ 服务端响应头严格 CSP（`default-src 'none'`），双重隔离，报告里的脚本不会执行、外链资源不会加载
- 基金详情页「AI 提示词」按钮复用同一套提示词生成器（`GET /api/v1/ai-prompt?code=005827&format=html|markdown`）

基金详情页「研究报告」区与之联动：

- 「新增报告」默认关联当前基金（复用同一上传弹窗）
- 「关联已有」可从报告库中挑选报告挂到当前基金（`PATCH /api/v1/reports/{id}`）
- 每份报告卡片只显示纯文本摘要，详情（AI 要点、风险、HTML 沙箱预览）统一走「查看」
- AI 解析对 HTML 报告会先剥标签再交给模型，解析结果落库前也统一去标签（`stripTags`），避免存进一堆尖括号

## 入场门槛：设了持仓才进鸡舍

「自选」是观察池，「鸡舍」才是真的养鸡。判定口径统一为 `cost_price > 0 && shares > 0`（成本价与份额都填了才算建仓）：

- 领养时成本价 / 份额留空 → 只进自选，不进鸡舍
- 未入场的基金：不出现在鸡舍卡片、不计入鸡舍概况（持仓市值 / 累计盈亏 / 今日估算 / 涨跌家数）、不结算每日事件、不衰减、不参与「打扫前先照料」的检查，也不能喂食 / 抚摸（接口返回 `no_position`）
- 自选页卡片标「👀 未入场 / 未设置持仓 · 暂不进鸡舍」，按钮直接变成「设置持仓」；顶部有提示条与「未入场」筛选（`filter=watching`）
- 详情页「我的持仓」对未建仓的基金给出提示条，一键「设置持仓」
- 清空成本价或份额 = 退出鸡舍，回到自选观察（`PATCH /api/v1/funds/{code}` 传空字符串即清空）
- `GET /api/v1/funds` 额外返回 `positioned` / `watching` 两个计数；`GET /api/v1/yard` 额外返回 `watching` 与 `watchItems`

## 核心玩法规则

| 当日涨跌幅 | 事件 | 状态变化 |
| --- | --- | --- |
| ≥ +2% | 下金蛋 | 心情 +12，成长 +8 |
| +0.5% ~ +2% | 下蛋 | 心情 +8，成长 +5 |
| -0.1% ~ +0.5% | 散步 | 心情 +2，成长 +3 |
| -1.5% ~ -0.1% | 掉 1 根毛 | 心情 -6，成长 +2 |
| -3% ~ -1.5% | 掉 3 根毛 | 心情 -12，健康 -3 |
| ≤ -3% | 躲雨 | 心情 -20，健康 -8 |

- 连续上涨 ≥3 天：成长值 ×1.5；连续下跌 ≥3 天：进入情绪低谷，抚摸后恢复成长。
- 每 24 小时未互动：饱食 -10 / 心情 -5 / 健康 -2（有下限，鸡不会「死亡」）。
- 鸡舍天气由上证指数涨跌映射（晴 / 多云 / 阴 / 雨），影响全体心情。
- **等级只与陪伴时长和照料投入有关，与收益率无关**（产品价值观，勿改）。

## 照料与投研素材（互动要有实际投入）

互动不是点一下就完事，每次照料都必须留下真实的投研痕迹：

| 动作 | 前置要求 | 效果 |
| --- | --- | --- |
| 喂食 🌾 | 必须附一份**报告**（`report_id`）或一条 **≥20 字投资心得**（`note`） | 饱食 +25 / 亲密 +3 / 成长 2 + 加成（报告 +5，心得 +3） |
| 抚摸 🤲 | 必须写一条 **≥10 字心态笔记** | 心情 +15 / 亲密 +2 / 成长 1 + 加成（心得 +1），并解除情绪低谷 |
| 喂全场 🌾🌾 | 同一份素材（报告或 ≥20 字心得），成长加成递减 | 依次喂饱所有不饿的鸡 |
| 打扫 🧹 | 必须先把所有**饿了 / 打蔫**的鸡照料好（冷却中的鸡不算欠照料），且有 6 小时冷却 | 全体健康 +8 / 心情 +5 |
| 音乐 🎵 | 4 小时冷却 | 全体心情 +10 |

- 素材会写入「投研时间线」：基金详情页的「投研心得」区可查看与删除（`GET/POST /notes`、`DELETE /notes/{id}`）
- 用报告加餐时，若该报告还没关联基金，会自动挂到被投喂的这只鸡上
- 每日任务随之升级为真实动作：投研喂食 ×3、写下投资心得、巡视鸡舍（打开鸡舍 + 点开一只鸡详情）、打扫鸡舍（先照料再打扫）

## 主要接口

统一前缀 `/api/v1`，支持 Cookie 会话或 `Authorization: Bearer <API_KEY>`。

| 方法 | 路径 | 说明 |

AI 上传报告示例（Markdown / 纯文本）：

```bash
curl -X POST http://127.0.0.1:3290/api/v1/funds/005827/reports \
  -H "Authorization: Bearer fa_xxx" -H "Content-Type: application/json" \
  -d '{"title":"2026Q2季报解读","tags":["AI生成"],"content_type":"markdown","content":"...","parse":true}'
```

AI 上传 **HTML 报告**（重点支持的格式）：

```bash
curl -X POST http://127.0.0.1:3290/api/v1/funds/005827/reports \
  -H "Authorization: Bearer fa_xxx" -H "Content-Type: application/json" \
  -d '{"title":"005827 深度分析","tags":["AI生成","HTML"],"content_type":"html",
       "content":"<!doctype html><html><head><meta charset=\"utf-8\"><style>...</style></head><body>...</body></html>",
       "parse":true}'
```

`content_type` 可选 `html` / `markdown` / `text`；省略时自动识别（`.html` 后缀、或正文以 `<!doctype html>` / `<html` 开头即判定为 `html`）。

## 部署要点

- 单端口服务，PM2：`pm2 start ecosystem.config.cjs && pm2 save`
- 子路径部署：设置 `.env` 的 `BASE_PATH=/fundFarm`，Nginx 用 `proxy_pass http://127.0.0.1:3290;`（**不带尾斜杠**，保留前缀），前端全部走相对路径
- 根路径部署：`BASE_PATH` 留空即可
- 数据安全：`data/`（SQLite 库 + 上传报告）不在版本库中，部署时只覆盖源码，切勿整体覆盖运行目录
